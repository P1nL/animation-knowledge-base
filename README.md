# 动画作画交接知识库

题 A：聚焦**日式动画作画交接与返修指示中的术语消歧**，面向阅读日文制作资料的中文学习者，回答易混原词、交接条件和岗位职责，并给出出处、页码及适用范围。

**公网体验：[rag.semi-overt.com](https://rag.semi-overt.com/)**

可以尝试：“中1和中一有什么区别？”“作监补主要负责什么？”“这个时间表指タイムシート还是制作排程？”这个小topic中的相似字形、同词跨语境和岗位边界，容易让通用模型给出看似合理、实际混淆的回答，适合用原始资料检验RAG的收益。

已完成28页资料池、34条来源卡、三组问答对照及公网聊天入口。演示采用“云服务器转发 → 本机Dify”，需要本机保持在线；正常提问可能产生模型及搜索费用。详见[公网访问说明](docs/PUBLIC_ACCESS.md)。

## 项目简要说明

### 1. 实现方式与时间安排

复用现成组件完成资料处理、检索和问答，不训练模型、不自建通用RAG平台。当前交付链路为：

~~~text
相关PDF页 → 本地OCR → 对照原页整理知识卡 → Dify建库
提问 → 语境/隐私检查 → 向量＋关键词召回 → 按需Exa联网
     → DeepSeek生成 → 引用链接与措辞整理 → 回答
~~~

知识卡保留日文原词、中文解释、来源和页码，区分原文事实、整理推论与资料未说明的部分。问题不明确时先澄清，不把旧书中的经验直接当成所有工作室的现行规定。

| 日期 | 实际工作与安排 |
| --- | --- |
| 2026-10-25 | 确定窄主题，查看目录及目标页，准备首批12页OCR和13条来源卡，建立评测协议。 |
| 2026-10-26 | 接通Dify/BGE-M3，先跑10题开发预实验；再扩展至28页/34卡，冻结30题，完成三组90份回答、评分及来源/参考复核。 |
| 2026-10-27 | 准备阿里云Embedding＋Exa交付应用，执行6场景开发验收，修复引用与展示问题，开放公网访客入口。 |

时间安排是**先验证资料和小批对照，再扩大题量，最后补交付功能**。这样可以尽早发现选题或数据问题，而不是先导入全书、最后才检查效果。上表是推进日程，不是个人工时。

### 2. 开源RAG的选型考量

| 组件 | 用途与选择理由 |
| --- | --- |
| **Dify 1.18.0** | 复用知识库、Chatflow、模型接入、运行记录和聊天界面，把时间用于资料与评测，而不是重写平台。 |
| **PaddleOCR＋Python** | 在本机识别日文扫描页，保留文字、坐标和置信度，便于定位错字及跨栏读序问题。 |
| **BGE-M3＋Ollama** | 用于历史三组对照的本地向量化。固定检索模型，比较原始OCR与整理卡，避免同时改变多个实验条件。 |
| **阿里云 text-embedding-v4** | 当前公网应用的Embedding服务，复用兼容接口接入Dify；与历史BGE-M3实验分开记录。 |
| **DeepSeek Flash** | 使用现成回答模型，同轮评测固定模型与生成参数，只改变是否检索及资料处理方式。 |
| **Exa** | 补充需要时效信息或明确要求联网的问题；联网结果仍须核对来源与适用范围。 |

选型侧重**证据可追溯、实验变量可控制、失败可定位、交付速度快**。当前应用采用向量0.7、关键词0.3的混合召回，Top-K为4；这是初始配置，不是已证明的最优权重，也没有额外调用Reranker模型。详见[交付配置](docs/DELIVERY_CONFIGURATION.md)。

### 3. 数据收集、预处理及其评估

资料来自给定的224页日文扫描PDF，按交接、检查、返修和易混术语筛选28页。

1. **先定资料范围。** 根据目录和原页选取证据，记录PDF页序、可见页码与资料年代，再设计后续测试题，不按答案反向补写知识库。
2. **保留原始OCR。** 原图、文字、框坐标和置信度分别保存，原始识别结果作为基础RAG对照，不被整理文字覆盖。
3. **按完整知识单元整理。** 核对词头、栏位与语境，形成34条来源卡；不能把“中1”和“中一”统一归一化，或把相邻栏位拼成一个定义。
4. **保留引用边界。** 按知识卡标题分块，让正文、出处和页码一起进入检索；表格只整理已核对的字段与用途，不凭OCR读序恢复格位和时间关系。
5. **隔离语料和评测。** 开发题、测试题、参考答案与评分不进入知识库；原PDF、页图和凭据不放入公开源码。

预处理从“关键字是否正确、读序与语境是否完整、出处是否可回溯、下游回答是否改善”四方面检查。已通过原页核对发现词头漏字、跨栏串行和出处分离等问题，再用G1/G2对照观察整理效果。没有全文逐字真值，因此不报告字错率，也不把28页处理称为全书审读。

详见[数据准备](docs/DATA_PREPARATION.md)、[OCR问题样例](docs/OCR_REVIEW.md)及[资料扩展与测试冻结](docs/CORPUS_V2_AND_FINAL.md)。

### 4. 问答评估的设计与结果

重点是区分**检索本身的收益**与**数据整理的收益**，而不是预设RAG一定更好。

- **先开发、再冻结：** 10道开发题用于调试；另建30题，在运行前冻结题面、参考要点和评分规则，包括术语8题、情境10题、跨页综合6题、资料不足6题。
- **三组对照：** G0无检索；G1检索原始OCR；G2检索校订与语境整理卡。G1/G2使用同一28页来源池；三组固定DeepSeek模型、题面、温度及2048-token输出上限，新会话逐题运行。
- **先定义判据：** 每题记录必须命中的事实、关键错误、澄清/拒答条件和证据页。0分为关键错误，1分为部分正确或遗漏，2分为核心要点正确且适当处理语境。
- **答案与证据分别看：** 不因G0没有引用扣正确性分；检索覆盖、引用支持和资料不足时的行为单独分析，命中页码不等于回答正确。

2026-10-26的source-v2 / final-v1实验结果：

| 组别 | 回答数 | 总分／60 | 均分／2 |
| --- | ---: | ---: | ---: |
| G0：无检索 | 30 | 48 | 1.600 |
| G1：原始OCR检索 | 30 | 50 | 1.667 |
| G2：整理卡检索 | 30 | 60 | 2.000 |

同题比较，G2比G0改善10题，其余20题持平；G1只比G0净增加2分，并有3题退步。结果支持本轮资料整理对核心要点回答的帮助，也说明粗糙检索可能带偏回答。

**这些是单次非盲评的要点得分。** 题目来自同一本书，资料、命题与评分高度相关；资料不足题三组全部答对，区分度不够。已观察结果的题集只作为开发/回归资料，更强结论需要新题、独立评分及更多真实用户问题。

当前阿里云＋Exa应用另做了6场景开发验收，原始结果为9/12；引用链接和过强否定已修复并做离线及Code节点验证，未用新生成回答重评。它不是上述BGE-M3实验的同一配置，不能直接继承60/60成绩。详见[评测协议](docs/EVALUATION.md)、[30题结果](docs/FINAL_RESULTS.md)和[6场景验收](docs/DELIVERY_ACCEPTANCE_20261027.md)。

### 7. 失败案例与能力限制

| 问题 | 原因、处理及限制 |
| --- | --- |
| OCR漏掉“中一”的“一”，左右栏文字交错 | 小字、相似字形和多栏排版破坏语境。回到原页核对词头与栏位，原始OCR保留作对照；置信度不能代替核对。 |
| 空行分块使正文与页码、出处分离 | 只按文本格式切分，没有保护知识单元。改为按完整来源卡边界导入，保留证据上下文。 |
| 有检索反而答得更差 | FINAL-13中G1未召回“差替”词条，把回答带向画稿检查，得1分；G0反而得2分。相关片段不一定回答当前问题，需要核对召回内容与问题阶段。 |
| 参考答案或题面有问题 | 第61页“必要画稿”曾误写成“必要线条”；中文“时间表”也可能指制作排程或タイムシート。按原页纠错并单列敏感性分析，不为提高分数追溯修改旧实验。 |
| 联网回答有编号却没URL，或把缺证据写成确定否定 | 增加本地引用映射、证据边界提示和有限措辞修正规则。离线与Code节点回放已通过，仍需新的真实回答回归。 |
| “仅根据官网”未严格落实 | 查询词保留了限定，但证据中仍包含未确认官方身份的转述页。当前没有新增仅官网过滤，不能承诺此类问题只使用官方来源。 |

旧索引中的管理标签也曾被模型复述，已增加上下文展示过滤，保留正文、页码与引用元数据；没有因此重新向量化或改写旧回答。详见[回答输出修复](docs/ANSWER_OUTPUT_FIX.md)。
