# final-v1 三组正式实验运行约定

> 当前材料与展示约定见[材料说明](HUMAN_REVIEW_COMPLETION.md)。本文保留原阶段的版本、处理过程和评测结果，不追溯改写分数。

日期：2026-10-26。用户在冻结30题之后明确批准：新版独立索引、30题×3组生成，以及由助手评分分析。本次授权覆盖最多90次回答和各请求所需的检索片段外发，不包括整书/页图上传、发布、失败自动补跑或额外模型裁判调用。

## 冻结输入与分组

- 题目/参考：`evaluation/final_v1.json`，30题，运行前已冻结。
- 来源：`corpus/releases/source-v2/scope.json`及`cards.jsonl`，28页、34卡。
- 私有实验目录：`work/final-v1`，不同于`work/pilot-dev-v1`，不覆盖旧资料或成绩。
- G0：无检索；G1：28页原始OCR；G2：同一来源页池筛选整理的34卡。
- G1/G2分别创建独立知识库；G0/G1/G2分别创建独立未发布Chatflow草案。运行前确认新旧应用/知识库ID不重叠。
- 来源卡保留12条之前用户确认、22条核对待独立；接受核对材料用于这次实验不等于把标签改为。

## 同一模型与预算

| 设置 | 三组一致值 |
| --- | --- |
| 回答模型 | 用户已配置的DeepSeek `deepseek-flash` API别名 |
| temperature | 0 |
| max_tokens | 2048 |
| thinking | false |
| 节点自动重试 | 关闭 |
| 会话 | 每题/组新会话，无前题历史 |
| 检索 | G1/G2使用本地BGE-M3，top_k=4，不重排，无阈值过滤 |
| 执行顺序 | 固定题号顺序，每题G0→G1→G2；未做顺序随机化 |

总输出预算上限184320 tokens，不等于实际用量；输入用量和费用依真实返回记录，不预填估计为实测。API别名不代表锁定底层权重版本，保留运行日期和返回信息。

三个草案使用同一回答任务与模型设置，仅调整是否提供检索上下文；G0允许使用已有知识，不因为没有引文而判错。正式请求不发送`required_points`、`reference_answer`、评分规则或其他答案提示。

## 本地运行入口

```powershell
.\.venv\Scripts\python.exe -B -m scripts.prepare_final --accept-ai-reviewed --index
.\.venv\Scripts\python.exe -B -u -m scripts.run_final --authorize-paid-calls
```

这些是本次执行记录/恢复入口，不是新一轮免费重跑指令。准备阶段只做离线快照与本地向量化，运行器才会产生付费调用。运行器读取已保存的成功结果而不重发；发现已存在的失败/未完成请求即停下，不把它当作可免费重试。截断不升级为完整成功。

每次请求先写入attempt，再发送；保留SSE事件、实际答案、检索片段、用量和结束原因。三个工作流均在第一条付费请求前保存并读回模型/提示词/上下文/重试配置，G1/G2另检查知识库ID与检索设置。读回内容保存至私有`workflows/`。

## 评分与分析

- 沿用冻结的0/1/2分要点，每组30题、满分60。逐题读取实际答案、参考与返回证据，不按关键词命中自动判正确。
- 材料整理、命题和评分共用工作流程，评审非盲、未独立。报告明确这一限制，不称为独立真值。
- 完整答案和未分配评分保留在`answers.jsonl`/`ratings.jsonl`，评分另存`ai-ratings.jsonl`，理由/证据分析另存，不覆盖原始答案。
- 分别报告正确性、歧义/边界、返回证据覆盖、引用支持、资料不足处理；G0没有检索引文不扣正确性分。
- 题目参考若与原页矛盾，保留冻结输入与具体争议，单列影响/敏感性分析，不按输出改题、回填知识或挑题只报好结果。
- 报告全部30题的逐题分数、各组分母、同题配对差值、失败与反例。均分或满分题占比不自动命名为行业准确率，不作未经检验的显著性声明。
- G2同时改变筛选、翻译、结构和语境整理，G1/G2差值不能归因于单一OCR纠错。多个题共享知识点，不能假定30个题彼此统计独立。
