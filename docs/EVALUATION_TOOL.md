# 已保存回答与评分的离线汇总工具

## 用途与当前边界

`scripts/summarize_evaluation.py` 是 Python 3.12 标准库 CLI，只读取问题清单、已保存回答和显式提供的评分，输出 Markdown 汇总。无需安装第三方依赖，不访问网络、不运行模型、不调用付费 API，也不读取或修改知识语料。

当前 `evaluation/pilot.json` 有 10 道题：

- dataset split 为 `development_only`。
- dataset status 为 `draft_requires_source_and_human_review`。
- 每题 gold status 都是 `draft`，尚未完成人工复核。

**pilot 仅用于开发预实验，不能称作正式测试或 held-out 结果。** 即使回答和评分全部补齐，这一性质也不会改变。工具保留这些标签及警告，不修改既有评估协议、pilot、参考要点或评分规则。

## 输入

### `--questions`：当前问题 JSON

沿用 pilot 的对象结构：顶层 `split`、`status` 为非空字符串，`questions` 为数组，每题具有唯一非空 `id` 和非空 `gold_status`。预期题数来自该数组，不从 ratings 中出现的题数推断。

工具仅使用以上元数据与题号，不按 `required_points` 或题面做关键词匹配，也不依据参考要点生成评分。重复题号或缺少所需元数据会报错，避免错误分母与审核状态被隐藏。

### `--ratings`：JSONL

UTF-8 文件，每个非空物理行是一个 JSON 对象。输入可带 UTF-8 BOM；空文件、空行和纯空白行均允许。回答中的换行应使用 JSON 字符串的 `\n` 转义，不得将一个对象直接拆成多个物理行。

| 字段 | 约定 |
| --- | --- |
| `question_id` | 必填，必须精确对应 questions 中的 `id`。 |
| `condition` | 必填，只接受 `G0`、`G1`、`G2`，区分大小写。 |
| `answer_text` | 必填字符串，保存实际回答。空串或纯空白表示尚无回答，不计入已回答数。 |
| `score` | 必填，取整数 `0`、`1`、`2` 或 `null`。`null` 明确表示未评分；缺字段不是未评分的替代写法。布尔值、字符串、浮点数与越界整数均拒绝。 |
| `reviewer` | 有评分时必须是非空、非纯空白字符串。未评分时可省略、为 `null` 或为空字符串；若提供非 null 值，仍须为字符串。 |
| `notes` | 可选附加 JSON 字段；留在原输入中，不自动解释或归纳为失败原因。 |
| `citations` | 可选附加 JSON 字段；留在原输入中，不用于修改答案评分或推断引用质量。 |

有评分的记录必须同时有非空回答。空回答配 `0` 也会报错，而不是把“尚未回答”当作“答错”。已保存的实际拒答或澄清请求属于非空回答，其对错仍由显式评分决定。

每个 `(question_id, condition)` 只能有一条记录；重复记录即使内容完全一致也会报错。修改评分应先修订输入中的原记录，不以追加重复记录实现覆盖。本工具不支持多次运行、多评分者投票或自动合并。

JSON 格式错误、未知题号、未知条件、非法评分、缺少必填字段及已评分记录没有 reviewer 等，均直接报错并显示 ratings 物理行号。不会跳过坏记录或静默采用最后一条。输入全量校验成功后才输出报告；错误退出码为 `2`。

## 运行

在仓库根目录执行，`python` 指向可用的 Python 3.12。下列 ratings 文件应由实际回答与审核记录提供；命令本身不会生成回答或分数。

```sh
python -B scripts/summarize_evaluation.py --questions evaluation/pilot.json --ratings work/pilot-ratings.jsonl
```

默认将 Markdown 输出到标准输出。保存文件时：

```sh
python -B scripts/summarize_evaluation.py --questions evaluation/pilot.json --ratings work/pilot-ratings.jsonl --output work/pilot-summary.md
```

输入文件必须存在；不存在不等同于空结果。`--output` 的父目录须已存在，输出为 UTF-8，指定的已有报告会被替换；输出路径不能与任一输入路径相同。工具不会修改输入文件或为实验创建目录、调用模型。

## 如何理解覆盖率与分母

设问题清单共有 `N` 道题。三个条件分别以完整的 `N` 为预期题数：

- **已回答 A**：该组有非空 `answer_text` 的题数，不代表回答正确。
- **已评分 S**：该组有非空回答、显式 `0/1/2` 和非空 reviewer 的题数。
- **缺失回答**：`N - A`。缺少记录或回答仅为空白都计入此项。
- **缺失评分**：`N - S`。包括没有回答的题和已有回答但 `score=null` 的题；两种缺失列有重叠，不能相加当总缺失数。
- **回答覆盖率、评分覆盖率**分别应理解为 `A/N`、`S/N`。报告保留计数与预期总数，不把覆盖率写成准确率。
- **均分**：已评分题分数总和除以 `S`；报告另列 `S` 为均分分母，显示到三位小数。这是 0-2 分量表的均值，不是准确率。

`0` 是实际已提供的评分，必须计入分母。`null`、缺失记录与空回答不会被补成 0 分。当 `S=0` 时均分为“不可计算”，而非 0 分。

空 ratings 会显示每组 `A=0`、`S=0`、缺失回答和缺失评分均为 `N`，同时标记“没有结果”；不会出现 100% 或 0% 准确率。仅有未评分回答时也不会计算均分。

报告附逐题状态表，区分“缺失回答 / 未评分”“已回答 / 未评分”和显式分数。完整回答、reviewer、notes 与 citations 仍在原 JSONL 中，不复制为伪造的实验示例。

## 配对比较

- `G0-G1` 对照的方向明确为 **G1 - G0**。
- `G0-G2` 对照的方向明确为 **G2 - G0**。

各自仅选取同一题在两组中都已有评分的交集。先逐题计算差值，再用差值总和除以配对数；报告显示这一配对数作为分母。正值仅表示该配对子集上 G1/G2 的平均分更高。

不使用不同题目子集上的两个组均分直接相减，也不要求三组共同完成后才允许两两比较。两项对照可能有不同的配对子集；配对数为 0 时差值为“不可计算”。均分和配对平均差值均保留三位小数，统计时不预先舍入。

## 证据边界

- **不评分**：不根据关键词、引用数量或模型裁判推断正确性。任何非空回答都只计入回答覆盖数，不能自动得到分数。
- **不惩罚 G0 缺引文**：所有组都原样汇总输入 score；citations 不参与计分。输入评分者也应遵守既有协议，不因 G0 无检索引用而扣答案分。本工具无法判断人工输入分数背后的评分理由。
- **不宣称真实审核**：split、status、gold_status 和 reviewer 仅复述输入。非空 reviewer 不证明真实人工审核，更不能自动改变 gold 的草案状态。
- **不推断缺失结果或失败原因**：部分完成仅代表对应子集；notes 不被自动扩写，引用支持程度等其他维度仍需实际证据和单独评审。
- **不作统计显著声明**：配对差值只是描述性结果，不输出 p 值、置信区间、预设提升或全体准确率。
- **工具测试不等于实验结果**：下述合成测试只验证汇总逻辑，不说明知识库、任何模型或任何题目的实际表现。

## 必要测试

```sh
python -B -m unittest discover -s tests -p test_summarize_evaluation.py -v
```

测试覆盖完整配对、部分缺失、空结果、重复与非法输入、开发集与草案标签、CLI 输出分流和输入失败时不发布部分报告。测试 fixture 明确标记为 `SYNTHETIC TEST DATA`，仅在内存中构造；CLI 文件读写使用内存替身，不创建真实 evaluation 结果。`-B` 避免生成字节码缓存文件。
