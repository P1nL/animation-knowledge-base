## 1. 现在只需要填写两个Key

在项目本机私有文件`work/delivery-v1/secrets.env`中填写：

```dotenv
DASHSCOPE_API_KEY=
EXA_API_KEY=
```

- `DASHSCOPE_API_KEY`：阿里云百炼**华北2（北京）**地域的Key。
- `EXA_API_KEY`：供本Dify应用使用的Exa Key；不是开发工具连接的凭据。
- 不要填写到公开模板`deploy/delivery.env.example`，不要发送到聊天正文或Git。
- 其他值已经配置。DeepSeek回答模型继续使用当前工作区已配置的供应商，未读取、复制或清空它原有的Key。

### 已配置的阿里云参数

| 参数 | 值 |
| --- | --- |
| 模型 | `text-embedding-v4` |
| 模型身份 | 阿里云官方标注的Qwen3-Embedding系列；**不宣称等于开源Qwen3-Embedding-4B** |
| Base URL | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 默认向量维度 | 1024，沿用该API默认值，不代表旧BGE向量兼容 |
| 每批最多输入 | 10条 |
| 每条上下文声明 | 8192 tokens |
| 返回编码 | float |
| Dify模型供应商插件 | `langgenius/openai_api_compatible/openai_api_compatible`，已安装 |

阿里云官方亦提供业务空间专属北京域名：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`；旧北京域名仍可用，因此默认不要求另填WorkspaceId。若账户只有其他地域Key，不要直接混用；需要同步调整并核验地域端点，当前脚本仅接受北京官方域名。

官方依据：`https://help.aliyun.com/zh/model-studio/embedding-interfaces-compatible-with-openai`。模型别名、接口限额和实际可用性以账户服务为准，本轮没有带Key做真实调用。

## 2. 填写后激活

从仓库根目录使用PowerShell 7运行：

```powershell
.\.venv\Scripts\python.exe -B -m scripts.prepare_delivery --activate --authorize-source-transfer
```

`--authorize-source-transfer`表示允许将**source-v3的34条来源卡文本**发给阿里云进行付费向量化，并注册/验证该Embedding配置。PDF、页图、测试题、参考答案和评分不会发送。

激活命令将：

1. 检查Key非空、官方地域端点、模型及来源快照一致。
2. 注册阿里云Embedding配置，创建新的独立知识库。
3. 通过知识库PATCH明确设置模型和混合检索，再导入34条来源卡。
4. 等待索引完成并读回模型身份和检索方式。
5. 把新知识库和Exa secret绑定到这份独立交付草案，将就绪状态设为true。

该命令**不运行90题、不主动发起Exa搜索或DeepSeek回答、不发布应用**。完成后，在Dify中打开“动画作画交接·阿里云＋Exa交付草案”进行小批问答验收；此时提问会产生实际Embedding/回答费用，命中联网策略时另有Exa费用。

已有成功导入的文档不重复上传；记录为失败或不确定的文档不会自动重新提交。若超时仅表示索引仍在进行，可检查状态后用同一命令继续，不要删除私有状态重建。供应商SDK内部重试行为未在空Key阶段实测，不把脚本无自动重发解释成供应商端绝不会重试。

### 更换阿里云Key或修复已登记的凭据

修改私有`secrets.env`后，若Embedding凭据曾登记成功，先显式执行：

```powershell
.\.venv\Scripts\python.exe -B -m scripts.prepare_delivery --refresh-embedding-credentials --authorize-source-transfer
```

这条命令只更新当前模型的工作区级凭据；供应商校验可能调用Embedding并产生费用，因此仍需授权参数。它不要求Exa Key，不上传来源卡、不重试失败/不确定文档、不改变草案就绪状态，也不运行搜索或回答。若其他应用共用此模型凭据，更新也会作用于它们；不会修改旧BGE模型配置。

更新成功后，确认文档状态再运行原激活命令。失败或不确定提交仍需检查，**不要删除状态文件来绕过重复提交保护**。普通激活不会自动读取并覆盖已登记的Key；不要把“改了本地Key”理解为“服务端凭据已更新”。

## 3. 已配置的工作流

```text
提问
  → 就绪/范围/显式敏感信息检查，保留原问题并补充已核验别名
  → 未就绪或需澄清：直接提示，不调用外部模型
  → source-v3向量＋全文混合召回
  → 根据时效、明确搜索请求、术语覆盖不足等决定是否联网
      ├─ 不触发：记录原因
      └─ 触发：Exa一次搜索并获取正文片段，失败时说明未完成
  → 合并网络执行状态/临时证据
  → DeepSeek按原始问题回答，区分本地、联网与推论
  → 本地Code节点补齐引用网址，并限定“仅因缺证据而作确定否定”的首句
  → 输出整理后的回答
```

### 来源与两路召回

- 仅导入source-v3的34卡，维持28页资料边界；复核状态不提升。
- 定义/原文、中文整理、整理推论和页码分区导出；按H1卡片边界切块，上限2000 tokens，避免以空行分散出处。
- 知识库为`hybrid_search`，节点采用`weighted_score`：向量0.7、关键词0.3，最终Top-K=4，无分数阈值过滤。
- `reranking_enable=true`在这里表示启用Dify的加权融合，**不是另调一个Reranker模型**。权重是初始配置，不是实验得到的最优值；未宣称关键词日文分词或模型效果已通过真实验收。
- 旧BGE知识库和source-v2实验草案不修改，不将两个版本合并。

### 查询辅助与隐私

- 保留原始问题给最终回答节点；检索只增加已核验的术语别名，不用额外LLM自由改写。
- 不合并中1/中一，不把时间表自动认定为タイムシート；无明确指代时追问。
- 入站规则在远端Embedding之前检查常见凭据、邮箱、手机号、私有路径和显式内部资料表述；命中则不外发。
- 这些是有限的保守规则，不是完整DLP或可靠的语义隐私分类器。开场提示明确不要输入私有项目和个人信息。完全离线需求不能由云Embedding链路满足。
- 用户说“仅按本书/不联网”时不使用Exa；这里“不联网补充”不代表Embedding和回答API变成本地运行。

### 默认Exa策略

- `WEB_ENABLED=true`，不要求最终用户先开启开关。
- 显式搜索/查证、当前信息、问题要求核对冲突、没有本地结果或关键术语未被本地内容覆盖时触发。
- 仅按本书优先；不向外搜索内部审批、批准人等私人规则。
- 当前证据覆盖判断是**术语覆盖启发式**；没有另加裁判LLM，不能声称自动识别所有隐含矛盾或完整蕴含关系。
- “不用联网/无需联网/只看本书”等限制优先；“仅根据官网/公开来源”不被误判为书内限定。
- 外发查询按原顺序保留已识别的公开术语、功能、版本、年份、否定和关系，不发送整段问题/对话或本地来源卡。例如Blender 4.2与4.3的Grease Pencil兼容性限定会保留。
- 公开词表是有限规则：若仍有无法识别的名称、数量或限定，暂不调用Exa，提示用户澄清或改用明确的公开术语；不再静默丢掉这些限定进行泛化搜索。这不是完整自然语言隐私分类器。
- 每轮最多一次搜索、最多5条结果，搜索同时请求每页最多3000字符正文；去重后最多提供3个来源。初版不再自动追加contents请求。
- 不把仅有标题、摘要或空正文当作已核验依据。网页只作为临时证据，不自动入库。
- 缺Key/超时/非成功响应/无法解析均返回明确状态，不能假称联网核实。HTTP节点与LLM节点关闭自动重试；已检查当前HTTP执行器内部max_retries=0。
- Exa Key使用Dify secret环境变量和HTTP自定义鉴权，不作为Code节点输入。当前HTTP执行器对鉴权头日志做遮罩。

### 回答参数

沿用已配置的`deepseek-flash`，temperature=0，max_tokens=2048，thinking=false，无自动节点重试。任务要求保留日文术语、原问题约束、书内页码；联网标记W1等并给相应URL，区分历史与当前、原文与整理推论。

系统提示词收敛为领域范围、原问题、证据、歧义与边界、引用、表达和指令隔离七项原则，不再逐项枚举审批、空白模板等特定案例。回答先用自然中文解释含义，再将对应专业术语放在括号内；首次解释清楚后可用明确简称，不反复堆叠括号。不同术语不能为了通俗而混同，原文引用和用户要求的原样内容保持原样。网址映射与已实现的证据边界整理仍由finalize节点承担。

- `deploy/delivery.env.example`：可公开的空Key模板。

- `work/delivery-v1/sources/`：34份仅来源的内部导入文件。
- `work/delivery-v1/workflow-template.json`：空Key工作流模板，不含真实凭据。
- `work/delivery-v1/no-key-smoke.json`：真实空Key保护分支运行记录，不是联网问答验收。

如果只需恢复尚未激活的草案配置：

```powershell
.\.venv\Scripts\python.exe -B -m scripts.prepare_delivery --install-draft
```

脚本拒绝把已激活草案改回空Key草案。不要手动将`DELIVERY_READY`设为true绕过建库。

Code节点内嵌Python源码，修改脚本不会自动改变Dify。未激活时，上述`--install-draft`会同步修订后的图及本地空Key模板，保留来源快照和私有Key文件；已激活草案的更新不走这个重置入口。
