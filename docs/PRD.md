# PRD：日式作画交接与返修指示问答助手

日期：2026-10-26。状态：P1本地资料、12页原始OCR、Dify/BGE-M3与13条来源草案索引已落地；Chatflow知识检索节点实测成功，回答模型配置入口已准备。校订和真实模型问答效果尚未验收。

## 用户与问题

面向阅读日式动画制作资料的中文学习者。核心问题不是一般动画常识，而是容易混淆的原词、作画/排期语境、检查责任和返修交接。

## 范围

1. 中1/中一、中なし等易混写法和跨语境术语。
2. 中割、タップ割り及相关操作条件。
3. 原画、二原、动画及交接关系。
4. 演出检查、作监检查、动画检查及返修沟通。

优先依据已定位的书内第 56–61、151–152、165–167 页，按需要补充相关术语页；不将全书所有主题无差别导入。问题不明确时说明可能语境或追问，不强行给出唯一含义。

## 数据事实与边界

- 给定 PDF 共 224 页，已检查目录和目标页；抽查页面为日文扫描图文，需要 OCR 和校订。
- 第 224 页记录 2009 年初版、2011 年第二次印刷。回答标注资料年代，不推定为 2026 年所有工作室通用的强制规范。
- B 站视频是补充参考。当前未取得并核对正文/字幕，不把标题当作已处理内容。
- 公开源码不包含整本书、整页扫描图或私人来源路径。公开视频、图片和引文的展示范围需确认。

## 用户功能

- 中文/日文提问，保留关键日文原词。
- 输出结论、语境差异、处理建议、证据和不确定范围。
- 回答可定位至来源与页码，资料不足时追问或拒答。
- 公开演示入口，采用必要访问与用量限制；不做复杂账户系统。

## 技术选型

用户已确认采用 **Dify + PaddleOCR + BGE-M3 + 用户可配置的现成回答模型** 的技术路线。本地项目默认使用DeepSeek Flash系列API，调用名deepseek-flash，用户自行填写凭据并可更换服务；同一轮评测固定模型和参数。选型确认不等于部署完成，也不包含付费调用、资料外发或公开发布授权。

| 层次 | 选择 | 原因与边界 |
| --- | --- | --- |
| PDF/数据脚本 | Python + pypdf / Pillow | 首批直接提取给定扫描件的整页图像；不建设通用 PDF 渲染平台 |
| OCR | 本地 PaddleOCR 3.7.0 + PaddlePaddle 3.3.1 CPU | 已处理12页；三页抽样有错字与跨栏问题，不把自动识别直接当真值 |
| RAG 应用 | 本地Dify 1.18.0 | 复用经典知识库与Chatflow；已部署，不自建向量库平台 |
| Embedding | BGE-M3，经Ollama 0.40.11 CPU运行 | 实测1024维，已完成本地索引与检索；不等于回答效果通过 |
| 回答模型 | 用户可配置；本地默认DeepSeek Flash系列API（deepseek-flash） | 用户自行配置API Key、地址与模型；同一轮G0/G1/G2固定版本、参数和题面 |
| 评估 | Python + 评分，Ragas 辅助 | 参考答案优先，不用自动裁判代替真值 |
| 发布 | Dify 托管或同套服务自托管 | 根据资料外发与宿主条件选择，公网入口必须真实可用 |

本地页图工具锁定 pypdf 6.10.0 与 Pillow 12.3.0；OCR依赖与参数见 [OCR说明](OCR.md)。Dify与Embedding已部署；回答模型插件和草案引用已准备，但没有密钥或真实生成。全部模型的实际配置步骤、版本、默认参数与验收边界集中记录在 [模型配置手册](MODEL_CONFIGURATION.md) 和 [本地部署手册](LOCAL_DEPLOYMENT.md)。

## 不做

全书百科、通用 RAG 框架、模型训练、任意图像问答、复杂用户后台、无授权公开原文或引用无出处的行业结论。

## 成功条件

数据处理可追溯；有独立评测集；无检索/基础 RAG/校订 RAG 的逐题结果可比较；公开 URL 可用；失败与资料不足行为如实记录。题目要求的明显提升需要实验支持，不由选题名称或框架选择自动成立。
